# Лабораторная работа №4: Разработка параллельного алгоритма умножения матриц по технологии OpenCL

Данный проект реализует параллельное умножение квадратных матриц с использованием технологии OpenCL (адаптировано под видеокарты AMD Radeon). 

Программа автоматически генерирует случайные матрицы, выполняет вычисления на GPU и проводит серию бенчмарков для различных размеров матриц и конфигураций локальных рабочих групп (размеров блоков).

## Цель работы
Изучить эффективность параллельных вычислений на GPU и проанализировать влияние размера блока (block size / local work size) на общую производительность умножения матриц.

## Возможности программы
* Автоматическая генерация случайных квадратных матриц типа `double`.
* Чтение исходных данных и запись результирующих матриц в текстовые файлы.
* Параллельные вычисления на GPU силами тысяч потоков через OpenCL Kernel.
* Автоматизированный бенчмарк (перебор размеров матриц от 200 до 2000 и блоков 8x8, 16x16, 32x32).
* Аппаратный замер времени выполнения с точностью до наносекунд.
* Расчет производительности в GFLOPS и сохранение итогов в CSV-файл.
* **Автоматическая верификация** результатов с помощью скрипта на Python (NumPy).

## Алгоритм
Каждый рабочий поток OpenCL (Work-item) вычисляет ровно один элемент результирующей матрицы:
$$C[row][col] = \sum_{k=0}^{N-1} A[row][k] \times B[k][col]$$

Используется двумерная сетка глобальных потоков (`Global Work Size`) и локальных блоков (`Local Work Size`).

## Анализ результатов

1. **Колоссальный прирост скорости:** Перенос вычислений на GPU дал многотысячное ускорение. Матрица $2000 \times 2000$ на CPU считалась более 5 минут, в то время как графический процессор справился с задачей всего за **0.046 секунды**.
2. **Влияние размера блока:** * На микро-размерах ($200 \times 200$) блоки $16 \times 16$ и $32 \times 32$ сразу показывают производительность в 2.5 раза выше, чем $8 \times 8$, за счет более плотной утилизации вычислительных блоков GPU (вейвфронтов).
   * Начиная с размера $800 \times 800$, блоки **$16 \times 16$ и $32 \times 32$ стабильно опережают блок $8 \times 8$** примерно на 12–14%.
3. **Стабильность вычислительного конвейера:** Пиковая производительность зафиксирована на отметке **388.79 GFLOPS** (размер 400, блок 8x8). На больших матрицах производительность стабилизируется в районе **340–350 GFLOPS** для блоков $16 \times 16$ и $32 \times 32$. Разница между ними минимальна, так как оба размера эффективно скрывают задержки при обращении к глобальной видеопамяти.

## Вывод
Использование OpenCL позволяет эффективно использовать параллельную архитектуру современных видеокарт для тяжелых математических задач. Для данной конфигурации оборудования оптимальным выбором являются размеры блоков **16x16** и **32x32**. Автоматическая верификация через Python (NumPy) полностью подтвердила корректность выполненных на GPU расчетов.
